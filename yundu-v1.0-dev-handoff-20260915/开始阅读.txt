云渡文件交换平台 V1.0 开发交付包
打包日期：2026-09-15

本包仅包含最新开发定稿及配套资源，没有程序源码，不包含旧版本需求、开发中间脚本、真实凭据或生产配置。

一、开始使用
1. 解压到计划开发的项目目录。
2. 将“给Codex的开发指令.txt”中的完整指令交给 Codex。
3. 让 Codex 阅读 01-documents 中唯一的 Word 开发定稿，按文档的开发阶段实施。
4. 产品标识直接使用 02-brand 中的 SVG；Zabbix 模板及接口样例位于 03-monitoring。

二、文件清单
01-documents：最新版产品需求与系统设计，包含菜单、权限、流程编排、管理员代办、数据库、REST API、部署、性能预算、Zabbix 监控及 AC01～AC64 验收要求。
02-brand：横版 Logo、独立图标、深色背景版与效果预览。SVG 为透明背景、文字轮廓，无需另外安装字体。深色背景版用于深色容器；预览 PNG 仅展示效果。SVG 可直接用于 Web，网站图标需在浏览器中检查缩小效果。
03-monitoring：Zabbix 7.0 原生 JSON 导出模板、只读监控接口 JSON 示例。示例时间为固定测试值，不能直接当作实时接口响应。
SHA256SUMS.txt：包内其他文件的 SHA256 校验值，路径相对于本包根目录。

三、已确定的关键边界
品牌：云渡；正式名称：云渡文件交换平台。
标语：生产与办公网络文件交换及审批。
技术栈：Go、React/TypeScript、Ant Design、MySQL、MinIO/S3。模块化单体与应用内后台任务，不做终端 Agent，不依赖 Redis、ClickHouse 或消息中间件。
登录：平台本地账号密码 + Microsoft Authenticator TOTP 动态验证码，不要求 Entra/OIDC。
方向：纯 Web 双向文件交换，来源门户上传、目标门户由申请人领取，不自动执行 SQL 或下发到机器。
办公到生产：仅 .sql/.csv，单文件均最大 30 MiB，每单最多 5 个、合计 150 MiB；全文基础文本与二进制特征检查，不做 SQL 语义/语法及 CSV 列数/公式审查。杀毒默认关闭，不能伪报杀毒通过。
审批：可视化编排、校验、模拟、发布和版本冻结；保留受权管理员代办并记录实际操作者及原因。
企业微信：群机器人通过指定 Proxy 发消息并 @ 当前处理人；自建应用个人消息不在 V1.0。
监控：Zabbix 7.0 通过 HTTPS + 只读 Bearer Token 采集，限制采集源；Token 无文件下载、审批及配置修改权限。模板默认每 30 秒采集，19 个监控项、16 个触发器。阈值只告警，不自动封禁或放行。
规模：约 30 人在线，60 人短时峰值；文件并发及资源预算按正式文档执行。

四、Zabbix 配置顺序
云渡开发完成后，在集成配置中设置 Zabbix 采集源白名单、签发只读监控 Token 并启用。
在 Zabbix 7.0 导入模板并绑定主机，配置 {$YUNDU.URL}、秘密文本类型的 {$YUNDU.TOKEN}，需要采集侧 HTTP 代理时配置 {$YUNDU.HTTP.PROXY}。
确认 HTTPS 证书和网络可达、Latest data 正常，然后按企业既有告警渠道配置 Action。
令牌只在签发时完整显示，支持撤销和重新签发。模板不含真实 Token，不自动配置告警接收人。
